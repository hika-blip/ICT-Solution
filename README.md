# ひたふら

地理特性と歩行能力に応じた避難支援Webアプリ（日立市）

testで追加した行です。

こんにちは

## 起動方法（Windows / コマンドプロンプト）

### 前提
- Python 3.12 がインストールされていること
- このリポジトリを `C:\dev\ICT-Solution` に clone 済みであること

### 初回だけ：仮想環境の作成とライブラリのインストール
```bat
cd C:\dev\ICT-Solution
python -m venv .venv
.venv\Scripts\activate
python -m pip install --upgrade pip
pip install -r requirements.txt
```

### 起動
```bat
cd C:\dev\ICT-Solution
.venv\Scripts\activate
uvicorn backend.main:app --reload
```
`Uvicorn running on http://127.0.0.1:8000` と表示されたら、ブラウザで http://localhost:8000 を開く。

- `--reload` を付けているので、コードを保存すると自動で再起動する
- 停止するときは `Ctrl + C`

### スマホ表示での確認
Chrome で `F12` → 左上のスマホのアイコン（デバイスツールバー）を押すと、スマホ幅で表示できる。

### 登録データのリセット
サーバを停止してから `data\app.db` を削除する。次の起動時に空の状態で作り直され、ユーザIDも 100001 から始まる。
（`data/` は `.gitignore` 済みのため、データベースは各自のPCにだけ存在する）

### 経路検索用の地図データの作成（初回だけ）
ログイン後のホームで経路検索するには、`data\map.graphml` が必要。`data/` は共有されないので、各自が次のコマンドで作る（日立駅〜常陸多賀駅の周辺、歩行用）。

```bat
python osm_to_network.py --bbox 140.620,36.542,140.674,36.601 --type walk --out data/map --no-map
```

- インターネット接続が必要。Overpass API が混雑して失敗したときは、少し待ってもう一度実行する
- 作ったあとはサーバを再起動する（地図データは起動時に1回だけ読み込む）
- ファイルが無くてもサーバは起動するが、経路検索だけ「地図データがありません」と表示される

続けて、坂道を考慮した経路検索のために標高を書き込む（国土地理院の標高タイルを使う。インターネット接続が必要）。

```bat
python scripts/add_elevation.py
```

- 地図データを作り直したときは、これももう一度実行する。実行後はサーバを再起動する
- 実行しなくても経路検索は使えるが、すべて平らな道として扱う（距離が一番短い経路になる）
- 経路は「所要時間が一番短いもの」を選ぶ。傾き5%以上の道（上り・下りとも）は坂道として、坂道での歩く速さで計算する。坂を避けて遠回りしたほうが早ければ遠回りし、遠回りでかえって遅くなるなら坂道を通る
  - 坂道の判定の傾き：`backend/routing.py` の `SLOPE_GRADE`
  - 坂道での歩く速さ：歩行ログを保存するときに、坂道を歩いた区間の距離と時間も記録して計算する（判定の基準は経路検索と同じ）。直近10回の記録で坂道を合計 `SLOPE_MIN_DISTANCE`（100 m）歩くまでは、ふだんの速さ × `backend/walks.py` の `SLOPE_SPEED_RATIO`（仮に 0.5）
  - 普通の道の速さは、歩行ログの坂道を除いた区間から計算する
  - 取得した標高タイルは `data/dem_tiles/` に保存され、歩行ログの坂道の判定に使い回す（無い場所だけ保存時にネットから取る）
  - この機能より前の歩行ログや、保存時に標高を取得できなかった歩行ログは、サーバの起動時に自動で計算し直す

### 施設（駅・学校など）のピンと入口の登録
施設・入口・避難先は、**管理画面（`/admin`）で追加・編集する**（下の「管理画面」を参照）。データの正本は DB（`data/app.db`）。
`seeds/` の CSV は、最初の読み込みと班での共有に使う。

- 起動時に DB の施設・避難先が空なら、`seeds/` の CSV から読み込む（CSV を直接編集したときは、管理画面の「CSVから読み込み直す」で反映する）
- CSV の形式は次のとおり（管理画面の「CSVに書き出す」で作られるものと同じ）

- `seeds/facilities.csv`：施設（`id,name,category,lat,lon,description,hidden`）※ `hidden` は 1 で非公開
  - `id` は英小文字・数字・ハイフンで、施設ごとに重複しない名前にする（例：`hitachi-station`）
  - `category` は `駅`・`学校`・`観光地`・`避難所` のどれか
  - `lat,lon` はピンを表示する位置
- `seeds/entrances.csv`：入口（`facility_id,name,lat,lon,note`）
  - `facility_id` は facilities.csv の `id`
  - 施設を目的地にすると、登録された入口のうち道のりが一番短いものがゴールになる
  - 入口の座標は、建物の出入口そのものではなく「歩いて着く道に面した位置」に置く（道から離れていると、近くの別の道につながって遠回りになることがある）
- `seeds/facility_areas.csv`：敷地（`facility_id,lat,lon`）※任意
  - 施設の外周の点を、外周に沿った順番で1行ずつ書く（3点以上）
  - 出発地・目的地にした地点が敷地の中なら、その地点ではなく、地点から一番近い入口（門）から経路を探す（地点から門までは直線距離で数える）
- 座標の調べ方：Google マップで入口の位置を右クリックすると、一番上に緯度・経度が表示され、クリックでコピーできる
- 地図を拡大（ズーム17以上）すると、入口の位置が青い点で表示されるので、位置が正しいか確認できる

### 管理画面（自治体向け）
施設（駅・学校・観光地など）と入口、指定避難場所・避難所の確認・追加・編集・削除、住民が投稿した公開ピンの削除ができる。
非公開のピンは管理者にも表示されない。

1. 管理者アカウントを作る（最初の1回だけ。住民のアカウントとは別で、画面からは作れない）
   ```bat
   python scripts/create_admin.py
   ```
   ログインID・表示名・パスワード（8文字以上）を聞かれる。
2. サーバを起動して http://localhost:8000/admin を開き、作ったログインIDでログインする
3. 「施設」「避難先」タブ：一覧の項目を押すと編集、「＋ 追加」で追加。位置は地図をクリックするか、印をドラッグして決める。
   「非公開にする」にすると、住民の画面・経路検索に出なくなる（削除せずに一時的に隠せる）
4. 「ピン」タブ：住民が投稿した公開ピンを確認・削除できる（写真のファイルも消える）
5. 「CSV」タブ：班での共有に使う
   - **CSVに書き出す**：管理画面の内容を `seeds/` の CSV に上書きする。commit・push すれば共有できる
   - **CSVから読み込み直す**：`seeds/` の CSV の内容で、施設・避難先を入れ替える。git pull したあとに押すと、みんなの内容がそろう（書き出していない変更は消える）
   - 2人が同時に編集して書き出すと GitHub で競合するので、編集する人を決めておく

### git pull のあとに動かなくなったら
他のメンバーがライブラリを追加した可能性がある。仮想環境を有効にした状態で、もう一度インストールする。
```bat
pip install -r requirements.txt
```

### ライブラリを追加するとき
```bat
pip install ライブラリ名
pip freeze > requirements.txt
```
`requirements.txt` の変更も一緒にコミットする。

### 変更を GitHub に上げる
main には直接 push せず、作業ごとにブランチを作って Pull Request を出す。
```bat
git switch main
git pull
git switch -c feature/作業名
（ファイルを編集）
git add .
git commit -m "変更内容"
git push -u origin feature/作業名
```
GitHub で「Compare & pull request」から Pull Request を作成する。

- 作成済みのブランチに戻るときは `-c` を付けずに `git switch feature/作業名`
- `a branch named ... already exists` と出たら、そのブランチは作成済み
